# FIN-01 검토요청

제출 상태: **READY_FOR_REVIEW** (계획서 §13). 승인 판정과 설계 결정은 설계 담당자 몫이며 이 문서는 FIN-02 착수를 선언하지 않는다.

## 1. 확인 완료한 사실

- 실행 환경 제약: 외부 호스트 egress 전면 차단(프록시 403, `host_not_allowed`), 자격정보 전무. 따라서 **실제 수집 검증 완료 출처는 0개**다. 공식 문서는 공식 도메인 검색 발췌로만 확인했다(연동검증표에 근거 수준 표기).
- 은행: 오픈뱅킹은 2025-01-02부터 법인 이용 확대(금융위·금결원). 이용기관 등록 + 보안점검(약 4주) + 은행별 조회대상 계좌등록 필요. 거래내역 페이지당 최대 25건, 거래별 고유 ID 없음. 웹케시 브랜치는 17개 은행 외화계좌 지원 표기, CODEF 는 기업 외화 거래내역 API 존재.
- 카페24: OAuth2 액세스 2시간/리프레시 2주, Leaky Bucket, 버전 헤더, ISO 8601.
- 광고: 메타 Insights 일별 `spend`·`account_currency`, 28일 소급 갱신(제3자 요약). 구글은 2026-09-09 개발자 토큰 폐지·Cloud 프로젝트 기반 접근·패스키 요구(공식 블로그 발췌). 네이버 `salesAmt`·`/billing/bizmoney`·StatReport 92일. 틱톡 일별 분해 30일/회, `advertiser/balance/get` 존재.
- 환율: 수출입은행 API 무료·일 1,000회·11시경 갱신·신규 도메인. ECOS 731Y001/0000001 무료 키. 서울외국환중개 08:30 공표.
- 검증 코드: 가상 샘플 49개 항목 통과(무중복 재수집, 관측 버전, 대체키, 페이징, 부분취소 연결, 일별 대체, 누적→월간, 휴일 환율, 정산입금·충전/소진·담당 원천 중복 방지). 저장소 typecheck/eslint/prettier 통과, 기존 코드 미변경.

## 3. 계획서 요구사항을 충족하지 못하는 부분(현 시점)

1. §4 "접근 가능한 소스는 실제 샘플 수집과 대조 완료" — 접근 가능한 소스가 없어 미충족. 조건부(접근 대기)로 남김.
2. §4 은행 필수 필드 "거래 ID" — 오픈뱅킹은 거래별 ID 를 제공하지 않아 대체키 사용 필요(§5 규칙으로 처리 가능하나 설계 확인 요망).
3. §4 은행 "기준일 잔액" — 오픈뱅킹 잔액조회는 조회 시점 잔액. 전일 마감 잔액은 거래후잔액에서 유도해야 함.
4. §1 "한국시간 10시까지 전일 자료" — 쿠팡 광고(익일 12:30 이후 안내, 판매자 광고 동일 여부 미확인)와 납품 엑셀(갱신 시각 미확인)은 10시 전 확정을 보장할 수 없음. 위하고는 월 단위 원천이라 전일 기준 자체가 성립하지 않음(계획서가 이미 구분).
5. §4 "사방넷에서 포함되지 않는 채널 명단" — 회사 전체 채널 목록 미확보로 명단 작성 불가. 주요 6개 중 쿠팡·무신사·스마트스토어·올리브영(온라인)은 사방넷 연동 근거 있음, 자사몰(카페24)·다이소는 미확인.
6. §4 광고 "세금 기준" — 5개 플랫폼 모두 미확인.

## 4. 설계 담당자가 선택해야 할 수집 경로와 비교 근거

- 은행 경로(§4 "최소 2개 후보 비교 후 선택"): 연동검증표 §2.1 표 참조. 요약 — A 오픈뱅킹: 공식 표준, 법인 확대 확인, 요금 저렴(보도 기준)이나 USD 미확인·거래 ID 없음·등록 약 4주. B 웹케시 브랜치: 외화 지원 표기, 필드·요금·갱신 미확인. C CODEF: 외화 API 존재, 스크래핑·인증서 운영, 요금 미확인. **세 후보 모두 실제 응답 미확보이므로 지금 기본 계약을 지정하지 않는 것이 계획서 §4에 부합한다.** 선택 전 필요한 정보: 각 후보의 5개 은행·USD·요금 회신.
- 환율 종류(§6): 수출입은행 `deal_bas_r` vs ECOS 매매기준율 vs 서울외국환중개 시장평균환율. 세 값의 정의가 다르므로 하나를 고정해야 한다. 수출입은행·ECOS 는 무료 키로 즉시 검증 가능.
- 자사몰: 사방넷이 자사몰 주문을 포괄하면 카페24 직접 연동 제외(§4). 포괄 여부 확인 전에는 미결.
- 채널별 담당 원천(§4): 사방넷/직접 API/납품 엑셀 중복 시 집계 원천을 채널·거래 유형별로 하나로 고정(가상 검증 X-03).
- 재조회 정책(§10): 연동검증표 §3 제안값 확정.

## 5. 사용자에게 필요한 계정·계약·자료 조치(없는 항목만, 한 번에)

비밀번호·토큰은 대화에 붙이지 말고 `fin/FIN-01/fin01.env.example` 의 변수명으로 서버 비밀 저장소 또는 로컬 `.env.fin01`(커밋 제외)에 설정한다.

1. 사방넷: API 서비스 가입 여부·요금, 연동키(마이페이지 > 서비스 관리 > 연동키/API 인증키 관리) 발급 상태, API 명세서 사본, 사방넷 연동 채널 목록.
2. 위하고: 현재 계약 상품에서 외부 읽기 연동(API/데이터 내보내기) 가능 범위·자격·비용 — 더존 담당자 확인.
3. 은행: 법인별 계좌 목록(법인·은행·통화·용도·사용 제한 자금 여부). 오픈뱅킹 검토 시 이용기관 등록 의사와 은행별 조회대상 계좌등록. 웹케시/CODEF 검토 시 영업 문의 회신(5개 은행·USD·요금·명세).
4. 판매·광고 계정: 법인별 판매자 계정(쿠팡 WING, 스마트스토어, 무신사 파트너, 올리브영, 다이소, 자사몰 플랫폼)과 광고 계정(메타 광고 계정 ID·System User, Google Ads 고객 ID·Cloud 프로젝트, 네이버 CUSTOMER_ID·API 라이선스, 쿠팡 광고 계정, 틱톡 광고주 ID) 목록과 법인 매핑.
5. 전체 채널 목록(약 40개): 채널명, 판매 방식(소비자/납품/혼합), 담당 원천 후보.
6. 납품 엑셀: 비식별 샘플 1개월분, 공유 위치와 접근 방식, 갱신 시각, 반품·수정·삭제 기록 방식.
7. 환율: 수출입은행·ECOS 인증키 발급(무료, 즉시) — 회사 명의 계정으로 발급 후 변수 설정.
8. 실행 환경: 검증 실행용 환경의 egress 허용 목록에 공식 API 호스트 추가(또는 자격이 있는 사내 환경에서 `--live` 실행).

## 6. FIN-02 공통 기반 착수 가능 여부와 근거

- 판단 근거(계획서 §4 마지막 문단: "FIN-02 공통 기반 착수와 미검증 소스의 운영 가능 판정을 구분"): FIN-02 범위(저장소, API/worker, DB, 로그인, 원본 저장, 코드 매핑, 중복/수정 기반)는 특정 외부 API 의 필드명에 의존하지 않는다. 이번 검증에서 원천키·payload 해시·관측 버전·(계정,일자) 대체·담당 원천 지정·UTC+원천 시간대 보존 규칙이 가상 데이터로 동작함을 확인했고, 은행 거래 ID 부재·조회 시점 잔액·취소 확정일 미확인 같은 제약은 §5 규칙(대체키, 관측 버전, 미확인 표시) 안에서 수용 가능하다.
- 따라서 **FIN-02 공통 기반은 착수 가능하다고 판단할 근거가 있다.** 단, 이는 설계 담당자의 결정 사항이며, 어떤 출처도 운영 가능 판정을 받지 않았다. FIN-03A(은행)·FIN-03B(판매·광고)는 §5 항목 회신과 실제 응답 확보 전에는 착수 근거가 없다.
- 계획서 변경 요청(해당 절·사유만): §4 은행 필수 필드 "거래 ID 또는 대체 식별" 에 오픈뱅킹 대체키 구성(핀테크이용번호+일시+입출+금액+거래후잔액+순번)을 명시할지 검토 요망. §10 재조회 정책에 연동검증표 §3 값을 채워 넣을지 검토 요망. 그 외 기술 스택·구조 변경 제안 없음.
