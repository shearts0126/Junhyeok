# FIN-01 검토요청

제출 상태: **READY_FOR_REVIEW** (계획서 §13). 승인 판정과 설계 결정은 설계 담당자 몫이며 이 문서는 FIN-02 착수를 선언하지 않는다. 2차 검토 지시(보완) 반영본. 항목별 조치는 `FIN-01_보완검토결과.md` 참조.

## 1. 확인 완료한 사실

- 실행 환경 제약: 시도한 공식 문서·API 호스트 29개 전부 egress 차단(프록시 403, `host_not_allowed`). GitHub·npm 레지스트리는 허용. 자격정보 전무. 따라서 **실제 수집 검증 완료 출처는 0개**다. 공식 문서는 공식 도메인 검색 발췌로만 확인했고, 구글 개발자 토큰 페이지는 설계 담당자가 원문을 확인했다.
- 은행: 오픈뱅킹은 2025-01-02부터 법인 이용 확대(금융위·금결원 발췌). 이용기관 등록 + 보안점검(약 4주) + 은행별 조회대상 계좌등록(발췌). 거래내역 페이지당 최대 25건(발췌). 발췌된 응답 필드 목록에 거래별 ID 는 보이지 않았으나 원문 미확인. 웹케시 브랜치는 17개 은행 외화계좌 지원 표기, CODEF 는 기업 외화 거래내역 API 페이지 존재(둘 다 발췌, 조건 미확인).
- 카페24: OAuth2 액세스 2시간/리프레시 2주, Leaky Bucket, 버전 헤더, ISO 8601(발췌).
- 광고: 메타 Insights 일별 `spend`·`account_currency`(발췌), 28일 소급 갱신(제3자 요약). 구글은 2026-09-09 개발자 토큰 종료·Cloud 프로젝트 기준 접근 수준(공식 원문), 신규 리프레시 토큰 발급 시 패스키(발췌). 네이버 `salesAmt`·`/billing/bizmoney`·StatReport 92일(발췌). 틱톡 일별 분해 30일/회·`advertiser/balance/get` 존재(발췌).
- 환율: 수출입은행 API 무료·일 1,000회·11시경 갱신·신규 도메인(발췌). ECOS 731Y001/0000001 무료 키(발췌). 서울외국환중개 08:30 공표(발췌).
- 검증 코드: 가상 샘플 49개 항목 통과(무중복 재수집, 관측 버전, 대체키, 페이징, 부분취소 연결, 일별 대체, 누적→월간, 휴일 환율, 정산입금·충전/소진·담당 원천 중복 방지). `--live` 는 요청 구성·전송까지 구현, 응답 파싱·대조 미구현(`FIN-01_실행결과.md` §8). 저장소 typecheck/eslint/prettier/unit 통과, 기존 코드·설정 미변경(`evidence/`).

## 3. 계획서 요구사항을 충족하지 못하는 부분(현 시점)

1. §4 "접근 가능한 소스는 실제 샘플 수집과 대조 완료" — 접근 가능한 소스가 없어 미충족. 조건부(접근 대기)로 남김.
2. §4 은행 필수 필드 "거래 ID 또는 대체 식별" — 오픈뱅킹 발췌 필드에 거래별 ID 가 보이지 않음(원문 미확인). 부재가 확인되면 대체키 사용 필요(§5 규칙으로 처리 가능하나 설계 확인 요망).
3. §4 은행 "기준일 잔액" — 오픈뱅킹 발췌상 `balance_amt` 는 조회 시점 잔액. 일자 지정 잔액 조회 가능 여부 미확인. 확인 전 안은 거래후잔액에서 유도.
4. §1 "한국시간 10시까지 전일 자료" — 쿠팡 광고(익일 12:30 이후 안내, 판매자 광고 동일 여부 미확인)와 납품 엑셀(갱신 시각 미확인)은 10시 전 확정을 보장할 수 없음. 위하고는 월 단위 원천이라 전일 기준 자체가 성립하지 않음(계획서가 이미 구분).
5. §4 "사방넷에서 포함되지 않는 채널 명단" — 회사 전체 채널 목록 미확보로 명단 작성 불가. 주요 6개 중 쿠팡·무신사·스마트스토어·올리브영(온라인)은 사방넷 연동 근거(발췌) 있음, 자사몰(카페24)·다이소는 확인하지 못함.
6. §4 광고 "세금 기준" — 5개 플랫폼 모두 확인하지 못함.

## 4. 설계 담당자가 선택해야 할 수집 경로와 비교 근거

- 은행 경로(§4 "최소 2개 후보 비교 후 선택"): 연동검증표 §2.1 표 참조. 요약 — A 오픈뱅킹: 공식 표준, 법인 확대 발췌 확인, 요금 저렴(보도 기준)이나 USD·거래별 ID·일자 잔액 미확인, 등록 약 4주. B 웹케시 브랜치: 외화 지원 표기, 필드·요금·갱신 미확인. C CODEF: 외화 API 페이지 존재, 인증서 기반, 요금 미확인. 세 후보 모두 실제 응답 미확보이므로 기본 계약을 지정하지 않는다. **선택에 필요한 남은 미확인 항목(후보별 1건씩 문의 대상)**: A — 외화계좌 조회 지원 여부와 이용기관 등록 조건(금결원 문의 1건). B — 5개 은행·USD·API 명세·요금(웹케시 문의 1건). C — 기업 외화 거래내역 지원 은행·요금(CODEF 문의 1건 또는 샌드박스 확인). 세 곳 모두에 문의하는 것을 선행조건으로 두지 않으며, 설계 담당자가 1~2개 후보를 지정하면 그 후보만 문의한다.
- 환율 종류(§6): 수출입은행 `deal_bas_r` vs ECOS 매매기준율 vs 서울외국환중개 시장평균환율. 정의가 다르므로 하나를 고정해야 한다. 선택 후 그 출처의 키 1종만 발급한다(두 종류 모두 발급을 선행조건으로 두지 않음).
- 자사몰: 사방넷이 자사몰 주문을 포괄하면 카페24 직접 연동 제외(§4). 포괄 여부 확인 전에는 미결.
- 채널별 담당 원천(§4): 사방넷/직접 API/납품 엑셀 중복 시 집계 원천을 채널·거래 유형별로 하나로 고정(가상 검증 X-03).
- 재조회 정책(§10): 연동검증표 §3 제안값 확정.

## 5. 사용자에게 필요한 조치(단계별)

비밀번호·토큰은 대화에 붙이지 말고 `fin/FIN-01/fin01.env.example` 의 변수명으로 서버 비밀 저장소 또는 로컬 `.env.fin01`(커밋 제외)에 설정한다. 환경 정책은 우회하지 않는다.

### ① 지금 필요한 최소 항목

1. **실제 수집을 실행할 수 있는 허용된 환경.** 본 원격 환경의 허용 목록 변경이 가능한지는 확인되지 않았다. 정식 대안: 승인된 사내 실행 환경(또는 회사가 관리하는 별도 컨테이너)에서 `--live` 를 실행하고 `results/live-run.json` 을 제출받는 방식.
2. **사방넷·위하고의 사용 상품과 연동 권한 확인**: 사방넷 API 서비스 가입 여부·연동키 발급 상태, 위하고 현재 상품에서 외부 읽기 연동(API/데이터 내보내기) 제공 여부(더존 확인). 명세서가 있으면 함께.
3. **첫 검증 대상 1개**: 계정 1개(예: 광고 계정 1개 또는 환율 키 1종) 또는 비식별 샘플 1개(예: 납품 엑셀 1개월분, 사방넷 주문 내보내기 1일분). 실제 응답 구조를 확인하는 것이 목적이다.

### ② 수집 경로 선택 후 필요한 항목

4. 설계 담당자가 지정한 은행 경로의 계약·자격정보(오픈뱅킹이면 이용기관 등록·계좌등록, 중계사면 계약·인증서 등록).
5. 선택한 환율 출처 1종의 인증키.
6. 해당 플랫폼의 읽기 권한: 메타 System User 토큰, 구글 Cloud 프로젝트 접근 수준 + 광고 계정 권한 있는 계정의 OAuth 동의(패스키), 네이버 API 라이선스, 틱톡 광고주 인가, 카페24 앱 권한(사방넷이 자사몰을 포괄하지 못할 때만).

### ③ 본격 연동 전 필요한 항목

7. 전체 계좌(법인·은행·통화·사용 제한 자금 여부)·채널(약 40개, 판매 방식)·광고 계정 목록과 법인 매핑.
8. 납품 파일 공유 위치·접근 방식·갱신 시각·반품/수정/삭제 기록 방식.

## 6. FIN-02 공통 기반 착수 가능 여부와 근거

- 판단 근거(계획서 §4 마지막 문단: "FIN-02 공통 기반 착수와 미검증 소스의 운영 가능 판정을 구분"): FIN-02 범위(저장소, API/worker, DB, 로그인, 원본 저장, 코드 매핑, 중복/수정 기반)는 특정 외부 API 의 필드명에 의존하지 않는다. 이번 검증에서 원천키·payload 해시·관측 버전·(계정,일자) 대체·담당 원천 지정·UTC+원천 시간대 보존 규칙이 가상 데이터로 동작함을 확인했고, 은행 거래 ID 부재 가능성·조회 시점 잔액·취소 확정일 미확인 같은 제약은 §5 규칙(대체키, 관측 버전, 미확인 표시) 안에서 수용 가능하다.
- 따라서 **FIN-02 공통 기반은 착수 가능하다고 판단할 근거가 있다.** 단, 이는 설계 담당자의 결정 사항이며, 어떤 출처도 운영 가능 판정을 받지 않았다. 외부 응답 확인 전 확정하면 안 되는 부분은 `FIN-01_보완검토결과.md` §6 에 열거했다. FIN-03A(은행)·FIN-03B(판매·광고)는 §5 ①②의 회신과 실제 응답 확보 전에는 착수 근거가 없다.
- 계획서 변경 요청(해당 절·사유만): §4 은행 필수 필드 "거래 ID 또는 대체 식별" 에 오픈뱅킹 대체키 구성 안(핀테크이용번호+일시+입출+금액+거래후잔액+순번)을 원문 확인 후 명시할지 검토 요망. §10 재조회 정책에 연동검증표 §3 값을 채워 넣을지 검토 요망. 그 외 기술 스택·구조 변경 제안 없음.
