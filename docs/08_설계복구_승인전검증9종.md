# 08. 설계복구 결정 — SKU 승인 전 검증 9종 (V1~V9)

| 구분 | 내용 |
|---|---|
| 결정일 | **2026-08-09** |
| 성격 | **Design Recovery Decision** — 유실된 원문을 대체하는 신규 확정 정책 |
| 적용 | T1-4A 부터. `05 §10.4` 의 "승인 전 검증 9종" 참조가 가리키는 실체 |

## 1. 배경 — 원 PRD §15.1 유실

기존 설계 문서(`05_API와_화면설계.md` §10.4, `07_개발백로그와_테스트전략*.md` T1-4)는
SKU 승인 요청(`POST /api/skus/{id}/submit`)의 검증을 **"승인 전 검증 9종 (PRD §15.1)"**
로만 참조한다. 그러나 그 원문인 **SKU·BOM 상세 PRD v0.1 §15.1 은 현재 repository 와
git 이력 어디에도 존재하지 않는다** (T1-4 preflight 에서 전수 확인 — 삭제 이력도 없음.
처음부터 repo 에 포함되지 않았다).

따라서 아래 V1~V9 를 **canonical SKU approval-validation contract 로 복구 확정**한다.
이는 원 PRD 를 발견했다는 주장이 아니라, 남아 있는 설계문서·확정 결정(D-06)·
오류코드 정책을 근거로 **새로 명시하는 정책**이다. 향후 원 PRD 원문이 발견되어
차이가 확인되면 이 문서를 정오 기록과 함께 갱신한다.

## 3. 결과 모델

단순 boolean 이 아니라 check 별 결과를 낸다.

```
SkuApprovalValidationResult { code, severity: ERROR|WARNING, status: PASS|FAIL|CHECK_UNAVAILABLE|NOT_APPLICABLE, message? }
SkuApprovalValidationReport { checks[], hasErrors, hasWarnings }
```

- `FAIL`+ERROR → submit/approve 차단 (422 `SKU_APPROVAL_VALIDATION_FAILED`, checks 반환)
- `FAIL`+WARNING → 진행 허용, 응답에 warning 포함
- `CHECK_UNAVAILABLE` → 판정 근거(패턴 등)가 아직 설계에 없음 — PASS 로 위장하지 않고 그대로 노출
- `NOT_APPLICABLE` → 검사 대상 모듈/데이터가 아직 없음 (V7~V9)

## 4. 검증 시점 — submit + approve 재검증 (신규 확정)

원 PRD 의 검증 시점 서술이 유실됐으므로 이번 결정으로 명시한다:
**submit 과 approve 직전 모두** report 를 계산한다. submit 후 approve 전 사이에
참조 공통코드 비활성화 등으로 상태가 변할 수 있기 때문이다. approve 시 ERROR FAIL 이
새로 발생하면 ACTIVE 전환 없이 PENDING_APPROVAL 유지 + 422 다.

## 5. T1-4 분할

| 단계 | 범위 |
|---|---|
| **T1-4A** | submit / approve / reject / deactivate, V1~V5 실검증 + V6 계약(CHECK_UNAVAILABLE) + V7~V9 slot(NOT_APPLICABLE), 권한 3종(`sku.submit`·`sku.approve`(reject 겸용)·`sku.deactivate`), self-approval(`allow_self_approval_sku`), 동시성, AuditLog |
| **T1-4B** | **archive** (BOM usage provider 필요 — `hasBomUsage=false` 상수 가정 금지로 연기), deactivate 의 활성 BOM 경고, V7~V9 실제 provider 연결, ARCHIVED 4전이(DRAFT/REJECTED/INACTIVE/DISCONTINUED → ARCHIVED, PENDING·ACTIVE → ARCHIVED 금지)의 domain matrix 반영 |

T1-4A 까지의 상태전이 matrix 는 기존 **allowed 4 / blocked 45** 를 유지한다 — ARCHIVED
전이는 T1-4B 에서 endpoint·usage provider 와 함께 한 번에 추가한다.
