# 설계 v0.3 보완 대기 목록

> **반영 기한: R1a-2(재고 코어) 착수 전**
> v0.2 승인 시 사용자가 지시한 필수 보완사항. 착수 전 반드시 설계에 반영하고 재승인을 받는다.
> 현재 상태: **미반영 (T0-1 구현 중)**

| # | 항목 | 대상 문서 | 영향 작업 |
|---|---|---|---|
| **1** | **SKU 단위 상시 음수재고 허용 금지** — `sku.negativeStockAllowed`만으로 음수를 허용하는 경로 제거. 거래마다 승인된 예외요청이 있을 때만 허용 (승인상태 `APPROVED` / 승인자 `ADMIN`·`SCM_LEADER` / 실행자≠승인자 / SKU·창고·허용수량·유효기간이 거래와 일치 / 사유 필수 / 사용 이력·감사로그) | `03`(예외요청 모델 신설), `04 §8.6` | `T2-9`, `T2-14` |
| **2** | **승인자 ID 직접 입력 금지** — `PostingCommand.approvedBy` 문자열 신뢰 제거. `allowNegativeStock: { approvalRequestId }` / `allowClosedPeriod: { approvalRequestId }` 로 변경하고, **같은 DB 트랜잭션 안에서** 승인자 권한·승인 상태·작성자 분리·승인 범위·유효기간을 재검증 | `04 §8.1`, `§8.6`, `§8.12` | `T2-5`, `T2-9`, `T2-14` |
| **3** | **멱등 요청 해시** — `inventory_transaction.request_hash` 추가. 동일 idempotency key + 동일 hash → 기존 결과 반환 / 동일 key + 다른 hash → **`409 IDEMPOTENCY_KEY_REUSED`**. hash는 정규화된 거래유형·원인문서·외부키·entries·사유 기준. **entry 순서만 다른 요청을 동일 요청으로 볼지 정책 명시 필요** | `03`(컬럼 추가), `04 §8.8`, `05 §10.18` | `T2-11` |
| **4** | **net=0 그룹 처리** — 원장행은 원본대로 저장하되 `inventory_balance`를 **갱신하지 않고 0수량 행도 생성하지 않는다**. `last_transaction_id`를 **"마지막으로 실제 수량이 변경된 거래"** 로 정의 (v0.2는 net=0도 갱신하도록 설계했으므로 수정 필요) | `03 §7`, `04 §8.7`, `§8.12` | `T2-9` |
| **5** | **거래유형별 균형 검증 (Validation Strategy 분리)** — 단순 전체 합계 0 검증 폐기<br>· `STATUS_CHANGE`·`RESERVATION`: 동일 SKU·창고·로케이션·LOT·유통기한·시리얼·소유자 단위에서 **상태 간** 순증감 0<br>· `WAREHOUSE_TRANSFER`: 동일 SKU·LOT·유통기한·시리얼·소유자 단위에서 **출발·도착** 순증감 0<br>· `ASSEMBLY`·`DISASSEMBLY`: 전체 합계 0 요구하지 않음. **조립지시서 + BOM 기준 검증**<br>· 일반 입고·출고·조정: 균형 검증 대상 아님 | `04 §8.4` | `T2-7` |
| **6** | **자가승인 설정 분리** — 전역 `allow_self_approval` → **`allow_self_approval_sku`** / **`allow_self_approval_bom`** 최소 2개로 분리. 재고조정·음수재고 예외·월마감 해제는 설정과 무관하게 **항상 금지** | `03 §7`, `05 §10.1`, `00 §15 D-07` | `T0-7`, `T1-4`, `T3-9` |
| **7** | **동기 업로드 조건** — SKU 490행·BOM 383행 동기 업로드는 다음 전부 충족 시에만 사용: ① 전체 행 검증 후 반영 ② bulk insert/upsert ③ **일부 성공 금지** ④ 중복 재실행 안전 ⑤ 실행시간 초과 시 미반영 ⑥ 처리시간 테스트 포함.<br>웹 함수 실행시간을 안정적으로 충족하지 못하면 **R1a-1·R1a-3은 관리자용 마이그레이션 명령(CLI)으로 제공**하고 웹 비동기 업로드는 R1a-4에서 구현 | `05 §10.4`·`§10.8`, `07 T1-11`·`T3-12` | `T1-11`, `T3-12` |

## 반영 절차

1. T0-1 ~ T0-9 (R1a-0) 완료
2. R1a-1 (SKU) 완료
3. **위 7건을 설계 v0.3으로 반영 → 사용자 재승인**
4. R1a-2 (재고 코어) 착수

> 항목 6·7은 R1a-0·R1a-1에도 영향을 주므로, 해당 작업(`T0-7`, `T1-11`) 착수 전에 먼저 확정하는 것이 안전하다.
