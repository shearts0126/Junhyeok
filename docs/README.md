## 핵심 결론 요약

### 1. 이 시스템의 본질

문제는 "엑셀이 흩어져 있다"가 아니라 **재고의 단일 진실 원천이 없다**는 것이다.
현행 `재고현황!V8 = VLOOKUP('2. 현재고')` — 3PL 스냅샷을 그대로 현재고로 쓰고 있고, 발주-입고는 문자열 결합키(중복 13건)로 연결되며, 입고 이력은 *"입고 후 삭제"* 로 소실된다.

→ 해결책은 하나다. **모든 재고 변동을 불변 거래원장에 원인문서와 함께 기록하고, 현재고를 그 집계 결과로만 산출한다.**

### 2. 데이터 실측으로 확인된 것 (PRD 서술과 다른 부분 포함)

| 항목 | 실측 | 함의 |
|---|---:|---|
| SKU 코드 중복 | **0건** | 전역 UNIQUE 안전 |
| BOM 구성품·상위 SKU 미등록 | **각 0건** | BOM 이관 위험이 예상보다 낮음 |
| **BOM 소요량** | **컬럼 자체 부재 → 383행 전량 미확정** | 🔴 **최대 병목.** 전용 확정 UI 필요 |
| BOM 리드타임 | **2/383행** | nullable 필수, 0 대체 금지 |
| 바코드 `-` | **376/490 (77%)** | ⚠️ 이슈로 만들면 큐가 무용지물 → **NULL 처리** |
| 바코드 `확인필요`/`확인불가` | **5건** | 실제 처리 가능한 규모 |
| 동일 바코드 다중 SKU | **2건** | 예외 승인 2건이면 끝 |
| **음수 기획세트** | **6건** (최대 −5,350) | 🔴 전부 올리브영 세트 = 조립거래 누락 |
| 현재고 미등록 SKU | **4건** (`FB-SB`는 코드체계 위반) | 선등록 필요 |
| 출고 RAW 미매칭 | **152/15,667 (1%)** | 코드 기반 매핑 전환 시 대부분 해소 |
| **출고 RAW 출고번호** | **없음** | 🔴 멱등성 구조적 불가 → R1은 원장 미반영 |
| 발주-입고 차이 ≠ 0 | **128/477 (27%)** | R2 과·미입고 정책 필수 |

### 3. 반드시 짚고 넘어가야 할 충돌 3가지

| | 충돌 | 권장 결정 |
|---|---|---|
| **C-01** | 가용재고 정의가 Master PRD(차감식)와 재고 PRD(상태이동식)에서 상충 | **상태이동식 채택.** 혼용하면 예약분이 이중 차감되어 소진예상일이 전부 왜곡됨 |
| **C-07** | 음수재고 차단(§3.2) vs 음수를 0으로 바꾸지 말 것(§26.3) — **양립 불가** | **실사 → 조립거래 소급 → 예외승인(5요건)** 3단계. 0 치환은 금지 |
| **C-09** | `inventory_balance` 재고키 UNIQUE인데 **NULL 정규화 전략이 미정** | **센티넬 값 채택** (`lot_no=''`, `expiry_key='9999-12-31'`). 이게 없으면 **현재고가 조용히 쪼개진다** — 음수재고보다 치명적 |

### 4. 기술구성 — 3가지 변경 제안

| # | 변경 | 사유 |
|---|---|---|
| 1 | **pg-boss + 전용 워커 추가** | Vercel Function 실행시간 상한(최대 300s) 때문에 10,000행 업로드가 완주 불가. 중간 타임아웃은 부분 반영 → 원자성 위반 |
| 2 | **Supavisor pooler + `directUrl` 분리** | 서버리스 커넥션 폭증 방지. **파생 제약**: transaction-mode에서 `pg_advisory_lock` 사용 불가 → 동시성 제어는 반드시 행 잠금 |
| 3 | **`xlsx`(SheetJS) → `exceljs`** | npm 배포판 취약점 이력 + 스트리밍 필요 |

나머지(Next.js, TS, PostgreSQL, Prisma, Supabase Auth/Storage, Tailwind, shadcn/ui, Zod, Vitest, Playwright, Vercel, GitHub)는 **적절하므로 유지**한다.

### 5. Release 1 범위 — 1a / 1b 분할 권장

세 PRD의 Release 1 정의가 서로 달라 합집합이 Master PRD 의도보다 2~3배 크다.

- **R1a (원장 코어)** — 기반·인증·공통코드·SKU·바코드·외부매핑·거래처·BOM·창고·**재고원장**·현재고·기초재고·수불부·업로드·감사로그·마이그레이션
- **R1b (재고 운영)** — 조정·실사·예약홀딩·월마감·3PL 대사·예외큐·대시보드

**1a 인수 완료 후 1b 착수**를 강력히 권장한다.
